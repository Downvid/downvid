DownVid 架构说明

Go 核心 + Wails 桌面壳 + Svelte 5 前端，单文件产物。

进程与职责

渲染进程 — app/frontend/src

Svelte 5 + Vite。界面状态在 store.svelte.ts，所有后端调用集中在 backend.ts（Wails 绑定适配层）。

↕ Wails 绑定（Go 方法 → 生成的 wailsjs）

Wails 壳 — app/app.go / app/bindings_*.go

只做参数搬运与事件广播，不含业务规则。

↕ 直接调用

Go 核心 — app/internal/*

16 个包，互相零依赖：解析、下载、直链、历史、设置、更新、依赖探测转发、系统交互。

↕ 起子进程（NDJSON 事件）

依赖边车 — backend/

探测 / 下载 yt-dlp、ffmpeg、ffprobe、aria2c。候选路径、镜像链、校验、解压与安装都在这里， 主程序只负责起进程与转发事件。

一次下载经过哪些环节

步骤位置说明
解析app/internal/parse调 yt-dlp，结果缓存 20 分钟；抖音/快手有专属解析器返回 CDN 直链
选格式app/internal/parse/formats.go同一清晰度只留一条，按编码兼容性挑（AVC > HEVC > AV1）
下载app/internal/download / app/internal/fetchyt-dlp 路径与直链分块路径完全独立；可选 aria2c 接管 HTTP 下载
进度app/internal/download/progress_line.go解析 [dvp] / [dvpp] 行，200ms 节流后广播
暂停app/internal/download/process_tree.go终止整棵进程树（进程组 / taskkill），避免 aria2c 变孤儿继续写盘
落盘app/internal/history历史原子写入 userData/download-history.json，上限 100 条

运行依赖为什么不随包分发

安装包只带一个约 18 MB 的单文件程序。yt-dlp / ffmpeg 按「系统优先，缺失才下载」的顺序解析： 手动路径 → ~/.downvid/runtime/bin → 登录 shell 的 PATH → 各平台常见安装目录。 这样用户机器上已有的版本会被直接复用，升级也不必等新版本发布。

边界规则：app/internal 的包之间不得互相 import、也不得依赖 cmd， 由 pnpm lint:boundaries 校验。每个包都能独立测试、独立替换。
